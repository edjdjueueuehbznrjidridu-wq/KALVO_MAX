راهنمای ساخت خودکار APK برنامه KALVO 7.2.3

برای نسخهٔ 7.2.3 فایل ZIP جدید را در ریشهٔ مخزن GitHub قرار بده. دو فایل Workflow داخل ZIP را نیز در مسیرهای زیر در مخزن ایجاد یا جایگزین کن؛ فایل‌ها را در همان مسیر نگه دار:
- `.github/workflows/build-apk.yml`
- `.github/workflows/build-boot-probe.yml`
Workflow اصلی ZIP سورس را خودکار استخراج می‌کند؛ Workflow دوم APK آزمایشی Kivy-only را می‌سازد.

۱) workflow ابتدا ZIP را استخراج می‌کند؛ پوشه‌های apex، assets، services، tests و tools و فایل‌های main.py و buildozer.spec باید پس از استخراج در ریشهٔ محیط build باشند.
۲) فایل `assets/kalvo_icon.png` آیکون لانچر برنامه است. فایل‌های `assets/sfx/*.wav` نیز برای افکت‌های اختیاری رابط استفاده می‌شوند.
۳) تغییرات را Commit و Push کن؛ با Push به main/master، workflow به‌صورت خودکار اجرا می‌شود. اجرای دستی از Actions > KALVO 7.2.3 Android APK > Run workflow نیز در دسترس است.
۴) ابتدا pytest، unittest، compileall و کنترل تنظیمات اندروید اجرا می‌شوند. فقط در صورت موفقیت job اعتبارسنجی، مرحلهٔ Buildozer آغاز می‌شود.
۵) پس از موفقیت، APK مستقیم را از بخش Artifacts دریافت کن. فایل `KALVO-7.2.3-Build-Info` شامل buildozer.spec، اطلاعات ساخت و SHA-256 است. اگر ساخت شکست بخورد، Artifact تشخیصی نیز بارگذاری می‌شود.
۶) برای ساخت برنامهٔ آزمایشی مستقل، از Actions گردش‌کار `KALVO Android Boot Probe APK` را انتخاب و Run workflow را اجرا کن. APK آن فقط Kivy را آزمایش می‌کند.

نکته: این نسخه از workflow مرحلهٔ Extract خودکار دارد؛ ZIP جدید را در ریشهٔ مخزن بگذار و فایل YAML جدید را نیز جایگزین کن.

هیچ کلید Coarena در ZIP جدید یا APK جاسازی نمی‌شود. کلید باید داخل تنظیمات برنامه یا محیط خصوصی وارد شود. اگر نسخهٔ قبلی با کلید واقعی در GitHub بارگذاری شده، آن کلید را از پنل ارائه‌دهنده باطل و کلید تازه صادر کن؛ حذف فایل از آخرین Commit، نسخه‌های قبلی تاریخچه را پاک نمی‌کند.

این workflow یک Debug APK نصب‌شدنی می‌سازد؛ Release signing و انتشار فروشگاهی فعال نیست. فایل ZIP مورد انتظار Workflow: `KALVO_7.2.3_BOOT_DIAGNOSTICS_PROBE.zip`. تمام معاملات در دفترکل محلی شبیه‌سازی می‌شوند و هیچ سفارش زنده‌ای به صرافی ارسال نمی‌شود.

سرویس foreground/sticky اختیاری است و پایش پس‌زمینه را در حدی که Android و سازندهٔ دستگاه اجازه دهند ادامه می‌دهد؛ Android می‌تواند آن را متوقف کند و Force Stop یا محدودیت باتری تضمین اجرای ۲۴ساعته را از بین می‌برد.
